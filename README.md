# Everwell Dental — Static Booking & Dashboard Prototype

Multi-page static dental clinic design (HTML + Tailwind CSS v4 + vanilla JS). This is the design/handoff prototype before the Drupal (`drupak2026`) implementation.

## Run

```bash
npm install          # first time only
npm run dev          # Tailwind watch mode (rebuilds assets/css/style.css on every change)
npm run serve        # optional: http://localhost:8080  (or use VS Code Live Server)
```

Production CSS: `npm run build` (minified). A built `assets/css/style.css` is already included, so the pages also open without running npm.

```text
    │   └── style.css        ← generated by Tailwind — do not edit

```

## Foundation (input.css)

- Colours live in `@theme`: `primary` (mint), `secondary` (teal), `tertiary` (gold), `body-bg`, `grey-bg`, `body-gray`, plus the named palette `ink, deep, panel, mint, teal, gold, sand, muted, line`. They work as Tailwind utilities, e.g. `text-mint`, `bg-deep/70`, `border-line`.
- Typography classes: `text-h1` … `text-h6`, `text-p` (fluid sizes and line heights from the CSS variables).
- Spacing helpers: `container-px`, `nav-px`, `container-pt`; `page-wrap` centres content and caps it at `--page-max` (1420px).
- To change fonts: edit the `@font-face` blocks and `--font-sans` / `--font-display` in `@theme`.

## Demo behaviour

- Booking form saves demo bookings in browser `localStorage` (status **Pending review**); the clinic dashboard can approve/reject, filter, and page through them; the doctor dashboard shows one doctor's appointments.
- Prototype only: no database, login, notifications, or double-booking checks. Do not enter real patient data.

## Drupal handoff

Doctors and services → content types; appointments → entity with server-side validation; dashboards → role-protected Views/routes (each doctor sees only their own appointments); email/SMS via a notification provider; add consent, spam protection and audit logging before production.
